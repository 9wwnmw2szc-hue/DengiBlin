# MASTER-ТЗ v1.0
# MARKETBRAIN — АВТОНОМНАЯ СИСТЕМА АНАЛИЗА РЫНКА И УПРАВЛЕНИЯ ТОРГОВЫМ ПОРТФЕЛЕМ

## 0. СТАТУС ДОКУМЕНТА

Данный документ является основным техническим заданием проекта **MarketBrain**.

Проект создаётся с нуля как отдельный продукт.

На первом этапе MarketBrain предназначен преимущественно для личного использования владельцем проекта.

Архитектура при этом должна сразу предусматривать возможность дальнейшего превращения MarketBrain в многопользовательский SaaS-продукт с регистрацией, тарифами и подпиской.

Основной брокер первой версии:

**Т-Инвестиции / T-Invest API.**

Первоначальная разработка и проверка торговой системы производится на виртуальных средствах и тестовом торговом контуре.

Переход к реальному брокерскому счёту допускается только после отдельного этапа тестирования.

---

# 1. КОНЦЕПЦИЯ

MarketBrain — автономная система анализа финансового рынка и управления торговым портфелем.

Система должна самостоятельно:

1. получать рыночные данные;
2. отслеживать доступные инструменты;
3. анализировать рынок;
4. анализировать отдельные активы;
5. анализировать свечи;
6. анализировать объёмы;
7. анализировать волатильность;
8. анализировать технические индикаторы;
9. анализировать стакан при наличии данных;
10. анализировать состояние рынка;
11. анализировать новости;
12. определять торговые возможности;
13. сравнивать несколько стратегий;
14. определять степень уверенности в сигнале;
15. определять риск;
16. определять размер позиции;
17. принимать решение BUY / HOLD / REDUCE / SELL / SKIP;
18. выставлять заявки через брокерский API;
19. контролировать открытые позиции;
20. самостоятельно определять момент выхода;
21. учитывать комиссии и фактическое исполнение;
22. сохранять каждое принятое решение;
23. оценивать результат каждого прогноза;
24. анализировать эффективность стратегий;
25. объяснять пользователю причины своих действий.

Основной цикл:

**DATA → ANALYSIS → SIGNAL → DECISION → RISK → EXECUTION → MONITORING → EXIT → RESULT → LEARNING**

# 2. ГЛАВНЫЙ ПРИНЦИП

MarketBrain не должен быть системой:

> «ИИ посмотрел на график и решил купить».

LLM/AI не имеет права непосредственно распоряжаться капиталом.

Торговые решения принимаются специализированными алгоритмическими модулями.

AI используется для:

- анализа неструктурированного текста;
- анализа новостей;
- классификации событий;
- объяснения решений;
- общения с пользователем;
- поиска закономерностей в истории;
- формирования исследовательских гипотез.

Финальное разрешение сделки проходит через независимый **Risk Engine**.

Ни один AI Agent, Strategy Engine или Decision Engine не имеет прямого доступа к брокерскому API.

---

# 3. РЕЖИМЫ

Система должна иметь два полностью разделённых режима.

## 3.1 SANDBOX

Виртуальная торговля.

Первоначальный виртуальный капитал:

**1 000 ₽.**

Пользователь должен иметь возможность изменять виртуальный баланс для тестирования разных размеров капитала.

Все функции MarketBrain должны быть доступны в Sandbox максимально близко к REAL.

---

## 3.2 REAL

Работа с реальным брокерским счётом пользователя.

Средства находятся исключительно у брокера.

MarketBrain НЕ является внутренним кошельком и НЕ хранит деньги пользователя.

Пополнение/вывод реального счёта производится через инфраструктуру брокера.

MarketBrain получает только необходимые разрешения для работы через API.

REAL должен быть визуально и технически отделён от Sandbox.

Переключатель:

**SANDBOX / REAL**

REAL нельзя активировать случайным нажатием.

Необходимо:

- повторное подтверждение;
- предупреждение о риске;
- проверка соединения;
- проверка Risk Engine;
- проверка торговых лимитов;
- проверка состояния брокера;
- явная фиксация включения REAL в Audit Log.

# 4. ПЕРВЫЙ РЫНОК

Первая рабочая торговая стратегия:

**ликвидные акции Московской биржи.**

Архитектура должна предусматривать дальнейшее подключение:

- акций;
- облигаций;
- фондов;
- валютных инструментов;
- фьючерсов;
- других поддерживаемых брокером инструментов.

Однако добавление нового класса активов не должно автоматически разрешать автономную торговлю им.

Каждый класс активов активируется отдельно после тестирования.

# 8. TECHNICAL ENGINE

Technical Engine анализирует:

- тренд;
- импульс;
- цену;
- объём;
- волатильность;
- уровни;
- пробои;
- ложные пробои;
- локальные максимумы/минимумы;
- положение относительно средних;
- изменение торговой активности.

Поддержать индикаторы:

- SMA;
- EMA;
- RSI;
- MACD;
- ATR;
- Bollinger Bands;
- VWAP;
- ADX;
- Volume indicators.

Архитектура индикаторов должна быть расширяемой.

---

# 9. CANDLE ENGINE

Свечной анализ является частью Technical Engine.

Поддержать разные таймфреймы.

Например:

- 1m;
- 5m;
- 15m;
- 1h;
- 1D.

Candle Engine может анализировать:

- структуру свечей;
- размер тела;
- тени;
- последовательности;
- импульс;
- разворотные формации;
- продолжение движения;
- свечи относительно объёма;
- свечи относительно тренда.

Свечной паттерн никогда не является самостоятельным достаточным основанием BUY.

Он является фактором общей модели.

---

# 10. VOLUME ENGINE

Отдельно анализировать объём.

Определять:

- аномальные объёмы;
- ускорение объёма;
- падение активности;
- подтверждение пробоя;
- расхождение цена/объём;
- необычную торговую активность.

---

# 11. MARKET CONTEXT ENGINE

Система должна понимать состояние рынка целиком.

Определять условные режимы:

**BULL / NEUTRAL / BEAR / HIGH VOLATILITY / RISK-OFF**

Учитывать:

- IMOEX;
- сектор;
- общую ширину рынка при наличии данных;
- волатильность;
- корреляции;
- валютные факторы;
- другие релевантные рыночные показатели.

Market Context влияет на итоговое решение.

# 12. NEWS ENGINE

Получать новости из разрешённых источников.

Новости классифицируются по:

- компании;
- сектору;
- рынку;
- типу события;
- потенциальной значимости;

Примеры:

- санкции;

- изменение руководства;

# 13. EVENT-DRIVEN REANALYSIS

MarketBrain не должен ждать следующей свечи, если произошло существенное событие.

Значимая новость или резкое движение рынка должны инициировать:

**EVENT → REANALYSIS → RISK CHECK → DECISION**

Если ситуация требует выхода:

**SELL / REDUCE**

может быть сформирован немедленно.

# 14. STRATEGY ENGINE

Создать модуль независимых торговых стратегий.

Минимальный набор:

### Trend Strategy

Торговля по тренду.

### Momentum Strategy

Поиск сильного импульса.

### Breakout Strategy

Поиск подтверждённых пробоев.

### Mean Reversion Strategy

Поиск возврата к среднему.

### Volume Strategy

Использование аномалий объёма.

### Combined Strategy

Объединение нескольких источников сигналов.

Каждая стратегия должна работать независимо.

---

# 15. STRATEGY COMPETITION

Создать лабораторию стратегий.

Каждая стратегия получает одинаковый виртуальный капитал.

Например:

**100 000 ₽ virtual.**

Они параллельно совершают виртуальные сделки.

Для каждой считать:

- P&L;
- P&L %;
- win rate;
- loss rate;
- average win;
- average loss;
- profit factor;
- expectancy;
- maximum drawdown;
- Sharpe;
- количество сделок;
- комиссии;
- результат относительно benchmark.

Результаты отображать в Strategy Lab.

---

# 16. SIGNAL ENGINE

Signal Engine объединяет результаты аналитических модулей.

Каждый сигнал должен иметь структуру:

- signal_id;
- instrument;
- timestamp;
- strategy;
- direction;
- strength;
- confidence;
- timeframe;
- supporting_factors;
- opposing_factors;
- market_context;
- invalidation_conditions;
- source_data_refs.

Запрещено создавать фиктивную confidence.

Если система отображает:

**Confidence: 74%**

значение должно иметь статистическое обоснование и быть откалибровано на исторических/forward результатах.

До появления достаточной статистики использовать:

**LOW / MEDIUM / HIGH**

или внутренний Score без заявления вероятности успеха.

---

# 17. DECISION ENGINE

Decision Engine принимает итоговое торговое решение.

Возможные решения:

**BUY**

**HOLD**

**REDUCE**

**SELL**

**SKIP**

Decision Engine учитывает:

- Technical Engine;
- Candle Engine;
- Volume Engine;
- Market Context;
- News Engine;
- стратегии;
- состояние портфеля;
- существующие позиции;
- ликвидность;
- состояние рынка;
- предыдущие сигналы.

Decision Engine НЕ отправляет заявку брокеру.

Результат передаётся Risk Engine.

---

# 18. RISK ENGINE

Risk Engine является обязательным шлюзом перед любой торговой операцией.

Главная цель:

**сохранение капитала и предотвращение неконтролируемых потерь.**

Для первой версии использовать умеренный профиль риска.

Risk Engine контролирует:

- максимальный риск сделки;
- максимальный размер позиции;
- максимальную долю одной компании;
- максимальный капитал в рынке;
- максимальное количество открытых позиций;
- дневной лимит потерь;
- максимальную просадку;
- корреляцию позиций;
- ликвидность;
- доступный капитал;
- торговый статус инструмента;
- аномальную волатильность.

Начальные значения должны храниться в конфигурации, а не быть жёстко зашиты в код.

Консервативные стартовые значения для Sandbox могут быть:

- риск одной сделки: до 1% капитала;
- одна позиция: до 15%;
- общий капитал в рынке: до 60%;
- дневной лимит потерь: 2%;
- максимальная допустимая просадка: 8%.

При маленьком капитале учитывать размер биржевого лота.

Если корректное соблюдение риска невозможно из-за минимального размера лота:

**SKIP TRADE.**

---

# 19. POSITION SIZING

MarketBrain самостоятельно определяет размер позиции.

Использовать:

- капитал;
- допустимый риск;
- stop distance;
- ATR;
- volatility;
- liquidity;
- confidence/score;
- текущие позиции;
- корреляцию.

Пользователь не обязан вручную указывать сумму сделки.

---

# 20. EXIT ENGINE

После покупки MarketBrain обязан продолжать анализировать позицию.

Возможные состояния:

**HOLD**

**REDUCE**

**SELL**

Exit Engine учитывает:

- первоначальную гипотезу;
- stop/invalidation;
- take-profit;
- trailing logic;
- изменение тренда;
- изменение объёма;
- новости;
- изменение рынка;
- волатильность;
- время нахождения в позиции;
- новую информацию.

Stop-loss и take-profit определяются системой динамически.

Однако Risk Engine должен устанавливать максимальные допустимые границы риска.

---

# 21. PORTFOLIO MANAGER

Portfolio Manager хранит состояние капитала.

Отображает:

- total equity;
- cash;
- invested;
- available;
- unrealized P&L;
- realized P&L;
- daily P&L;
- total return;
- positions;
- exposure;
- drawdown.

MarketBrain не обязан использовать весь капитал.

Решение:

**CASH / NO TRADE**

является нормальным торговым состоянием.

# 22. ORDER MANAGER

Единственный модуль, имеющий право инициировать брокерские заявки.

Цепочка:

**Decision Engine**
↓
**Risk Engine**
↓
**Portfolio Manager**
↓
**Order Manager**
↓
**Broker Adapter**

Order Manager:

- создаёт заявку;
- генерирует уникальный idempotency key;
- отправляет;
- проверяет статус;
- обрабатывает partial fill;
- обрабатывает rejection;
- отменяет;
- заменяет;
- фиксирует исполнение;
- предотвращает двойную отправку.

# 25. DECISION JOURNAL

Необходимо сохранять не только сделки.

Сохранять также решения:

**SKIP**

и

**HOLD**.

Это критично.

Иначе невозможно понять:

> какие возможности система пропустила?

Для каждого решения сохранять состояние входных факторов.

---

# 26. FORECAST VALIDATION

Каждый прогноз получает срок проверки.

После наступления срока система сравнивает:

**FORECAST vs ACTUAL RESULT**

и записывает результат.

На основании этого рассчитывать эффективность отдельных факторов и стратегий.

---

# 27. LEARNING ENGINE

MarketBrain должен учиться на собственной истории.

Но запрещено:

**автоматически менять production-стратегию без проверки.**

Правильный цикл:

**Production data**
↓
**Research**
↓
**Candidate Strategy**
↓
**Backtest**
↓
**Out-of-sample**
↓
**Paper Trading**
↓
**Evaluation**
↓
**Manual/controlled promotion**
↓
**Production**

Production и Research должны быть разделены.

---

# 28. BACKTEST ENGINE

Создать собственный модуль backtesting.

Он должен учитывать:

- исторические свечи;
- комиссии;
- spread;
- модельное slippage;
- размер лота;
- задержку исполнения;
- отсутствие look-ahead bias.

Обязательно разделять:

**training / validation / out-of-sample.**

Запрещено оценивать стратегию только на данных, на которых она подбиралась.

---

# 29. AI ANALYST

В MarketBrain должен быть встроен AI Analyst.

Интерфейс — чат.

Пользователь может спрашивать:

> Что сейчас происходит?

> Почему ты купил SBER?

> Почему не купил YDEX?

> Какие позиции наиболее рискованные?

> Что сегодня заработали?

> Какие ошибки были за неделю?

> Какая стратегия сейчас лучшая?

> Почему продали эту акцию?

AI Analyst должен отвечать на основании фактических данных MarketBrain.

Он не должен придумывать:

- цены;
- сделки;
- причины;
- новости;
- статистику.

Ответы должны иметь ссылки на внутренние evidence/data records.

# 80. ФИНАЛЬНАЯ ЦЕЛЬ

MarketBrain должен превратиться в систему, которой владелец может предоставить разрешённый капитал и сказать:

> **«Управляй им в рамках установленного риска».**

После этого MarketBrain самостоятельно:

**наблюдает → анализирует → ждёт → находит возможность → проверяет риск → покупает → контролирует → продаёт → оценивает результат → улучшает исследовательские модели.**

Но система всегда должна придерживаться принципа:

# СОХРАНЕНИЕ КАПИТАЛА ВАЖНЕЕ СОВЕРШЕНИЯ СДЕЛКИ.

Если MarketBrain не уверен или не имеет корректных данных:

# NO TRADE.
